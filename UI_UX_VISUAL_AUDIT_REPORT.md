# ORAC-IOS Portal Visual Audit Report

Date: 2026-10-27  
Scope: authenticated portal presentation only; no public-site, workflow, financial, V5, data, or deployment changes.

## Outcome

The portal shell and shared visual components were refined against the owner feedback and the supplied design-system references. The responsive audit passed at desktop, tablet, and mobile widths using fictional local Finance UAT data.

## Implemented visual rules

- A three-zone, 72 px application header: brand, labelled navigation, then account/actions.
- 44 px navigation and control targets with readable 16 px base typography.
- Tablet navigation switches to the accessible menu below 1280 px, preventing labels from being squeezed or clipped at 1024 px.
- Attention work appears before neutral totals; neutral metric cards are label-first, with counts visually subordinate to their purpose.
- Shared spacing, card, table, focus, status, empty-state, modal, tab, and form presentation rules keep pages visually consistent.
- Data tables retain a local scroll region instead of forcing page-wide horizontal scrolling.

## Issue found and corrected

The initial tablet screenshot showed that the desktop navigation could visually crowd its labels at 1024 px even though the page had no technical overflow. The desktop-nav breakpoint was moved from `lg` to `xl`; tablet and mobile now use the existing accessible navigation drawer, preserving full labels and touch targets. During the independent capture review, the mobile Finance page was also found to have been photographed while its data was loading. The audit now waits for that state to settle before recording evidence; the regenerated mobile screen passed.

## Deliberately not changed

- The public corporate site remains outside this portal-only scope.
- No logo was invented or copied into controlled PDFs. The backend has no approved shared PDF logo asset; adding one needs an explicitly approved source asset and a separate review.
- No role, route, API, commercial, tax, V5, database, or deployment rule changed.

## Recommended final release checks

1. Independent reviewer inspects the recorded desktop, tablet, and mobile screenshots in light and dark modes.
2. A user completes a keyboard-only and screen-reader smoke test on a real device/browser.
3. Review real controlled quotation, invoice, PO, job-card, and worksheet print samples once a single approved logo asset is available.
